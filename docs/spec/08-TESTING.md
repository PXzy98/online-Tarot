# 08 · 测试与验收

## 1. 命令

| 命令 | 内容 |
|---|---|
| `pnpm typecheck` | `tsc --noEmit` |
| `pnpm lint` | ESLint（包括架构边界规则和禁止 `dangerouslySetInnerHTML`） |
| `pnpm test` | Vitest 单元测试和属性测试 |
| `pnpm content:check` | 内容校验（06 §4） |
| `pnpm build` | `content:build` + `next build`（静态导出到 `out/`） |
| `pnpm verify:export` | 检查 `out/`：各语言页面齐全、78 × locales 个详情页都存在、`sitemap.xml`、`robots.txt`、`404.html`、`_headers` |
| `pnpm e2e` | Playwright（基于构建产物运行静态服务器） |
| `pnpm check` | 依次运行以上所有命令（CI 入口） |

## 2. 可测试性前提

- **随机源可注入**：引擎接收 `RandomSource`。测试中用 `seededSource('fixture-1')`，每次结果相同。
- **E2E 测试模式**：构建时如果设置 `NEXT_PUBLIC_TEST_HOOKS=1`，就允许通过 `?seed=` 固定随机源，通过 `?motion=off` 关闭动画。**生产构建不包含这些钩子**，`verify:export` 会检查这一点。
- **日期可注入**：每日一牌的逻辑接收 `now: () => Date`，E2E 中用 Playwright 的 `clock` API 控制时间。

## 3. 单元测试（必须覆盖）

1. 78 张牌：ID 和 slug 唯一；大阿尔卡那 22 张、小阿尔卡那 56 张、每个花色 14 张；编号符合 RWS（Strength = 8，Justice = 11）。
2. 元素归属与 04 §3.1 的表格一致。
3. `randomInt` 的取值范围；拒绝采样的边界（使用一个故意给出边界值的伪随机源）。
4. `shuffle`：结果是输入的一个排列，不修改原数组。
5. 抽 N 张不重复，数量正确，正逆位取值合法，“仅正位”模式下全部为 upright。
6. 状态机：所有非法事件被忽略；`START_SHUFFLE` 是唯一生成 DeckState 的地方；重复 `PICK` 幂等；`REVEAL` 前必须填满所有位置。
7. 各牌阵的位置定义正确，角色合法。
8. 解读：单张牌阵穷举（78 × 2 × 6 × locales）；三张牌阵用属性测试；黄金样例快照。
9. 存储：序列化往返一致；JSON 损坏、版本未知、ID 非法、存储不可用、超出配额时都回退到安全状态。
10. 每日一牌：同一天返回同一结果；跨天后重新生成；时区边界（用固定时区运行测试）。
11. 导入：超大文件、错误结构、非法 ID 都被拒绝，并给出提示。
12. 安全层：词表命中和级别判定。
13. i18n：`messages/*.json` 各语言键完全对齐；内容各语言的字段对齐。

## 4. 随机性测试

- 首要目标是**证明算法正确**：拒绝采样无偏，Fisher–Yates 实现标准。用确定性测试覆盖这两点。
- 统计测试辅助检查明显偏差：对 `randomInt(78)` 采样 78,000 次，做卡方检验，显著性阈值设为 α = 0.0001，降低偶发失败的概率。对 3 张牌的位置分布也做类似检验。这类测试放在单独的 `test:stats` 中，CI 每天运行一次或手动运行，不阻塞日常提交。

## 5. E2E（Playwright）

设备：桌面 Chromium 1280×800；移动端 iPhone 13（390×844）和 Galaxy S 系列小屏（360×640）。

用例：
1. 首页 → 开始占卜 → 单张牌完整流程
2. 三张牌（两种牌阵各一次），每种都选择不同的问题类型
3. 固定 seed 下，指定位置出现逆位，界面上显示“逆位”文字
4. 结果页存在联系段，并且可以展开“依据”
5. 保存历史 → 历史页可见 → 打开 → 删除 → 清空
6. 每日一牌：刷新后不变；推进时钟到第二天后变化
7. 没有本地记录时：结果页和历史页显示空状态
8. 移动端：在横向牌带中滑动到第 70 张以后再选牌；切换到网格视图后选牌；360px 下没有水平溢出
9. 仅用键盘完成一次三张牌占卜
10. 语言切换：在选牌过程中切换语言，进度保留；结果页切换语言后解读变为另一种语言
11. 危机词表命中时，求助卡片显示在最前面
12. axe：每个主要页面零 serious / critical 违规
13. Reduced Motion 模式下流程完整可用

## 6. 性能（真实测量，不得捏造）

- 在 P6 对构建产物运行 Lighthouse（移动端预设），记录首页、占卜页、卡牌详情页的分数和环境。
- 目标：LCP ≤ 2.5s，INP ≤ 200ms，CLS ≤ 0.1，Accessibility ≥ 95，Performance 尽量 ≥ 90。
- 没有达标时如实记录，并列出改进项。
