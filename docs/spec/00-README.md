## 执行顺序

工程线与内容线**并行**，在 P4 汇合：

```
工程线:  P1 基础工程 → P2 核心引擎 → P3 占卜交互 → P4 解读引擎 → P5 内容页面与附加功能 → P6 质量与部署
内容线:  C0 内容基建 → C1…C11 卡牌批次（每批中英双语） → C12 引擎短语库
                                   └──── P4 需要 C0 + 至少 C1；P6 上线需要内容线全部 reviewed
```

**一个会话只执行一份任务单。** 任务单验收通过并提交后，再开新会话执行下一份。不要在一个会话里连跑多个阶段。

## Agent 通用守则（所有任务单共用，不再在各文档重复）

1. 动手前先看仓库现状，复用已有实现，不随意覆盖。
2. 只汇报真实执行过的命令和真实结果。没跑的测试写“未执行”及原因；未完成的写“未完成”。
3. 不留假交互：没有无效按钮、未实现菜单、TODO/Lorem 占位内容进入生产构建。
4. 非关键的不确定点按合理默认推进，并记入 `DECISIONS.md`；关键分歧（影响产品或合规）停下来问。
5. 依赖使用执行时的最新稳定版并锁定（`pnpm-lock.yaml`）；版本相关结论以官方文档与实际构建为准。
6. 冲突时的优先级：安全/隐私/版权 > 功能正确 > 内容质量 > 体验与无障碍 > 可维护性 > 性能 > SEO > 装饰 > 未来扩展。
7. 每份任务单结束时：运行该单列出的验收命令，提交到指定分支，并在提交说明或会话总结中列出“完成 / 未完成 / 已知问题”。

## 术语

- **Reading（一次占卜）**：一次完整的牌阵抽牌及其结果。
- **Draw（抽出项）**：牌阵中一个位置上的 `{ positionId, cardId, orientation }`。
- **Deck Pack（牌面包）**：一套牌面图片及其授权记录，可整体替换。
- **Locale**：语言版本，当前为 `zh`（简体中文）与 `en`（英文）。
- **Signal（信号）**：解读引擎从牌阵中识别出的可解释特征（如元素关系、重复数字）。
